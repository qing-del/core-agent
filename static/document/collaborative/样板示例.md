# V1 时代

## 节点形式

- 扁平文本内容：
````md
# CORE AGENT 文档编辑设计

这是一个基于 **Tiptap + Yjs** 的协同编辑器。

目前 V1 的目标是：让 AI 通过 `Tool` 修改文档，而不是直接处理底层的 Yjs 数据。

## V1 编辑原则

AI 主要处理以下几种内容：

- 普通文本修改
- **加粗文本**
- *斜体文本*
- ~~删除线文本~~
- `inline code`
- 插入资源引用，例如 [[Yjs 架构设计]]

> AI 不应该直接感知 Y.Doc、RelativePosition 或 Yjs Update。

### 基础操作

1. 找到目标语义块
2. 在目标块内部定位文本
3. 执行插入、删除或者替换
4. 将修改转换成协同编辑操作

---

下面是一段代码：

```java
public void updateDocument(String documentId) {
    System.out.println("update document");
}
```
````

## Yjs 的原子事务

- 可以理解为以下的操作流程
```txt
一次语义编辑
    ↓
确定来源 origin
    ↓
Tiptap / ProseMirror 执行修改
    ↓
binding 将修改写入 Y.Doc Transaction
    ↓
Y.Doc 已完成修改
    ↓
Transaction 产生一次协同 update
    ↓
ydoc.on('update') 拿到：
    update + origin
    ↓
REMOTE？
├─ 是 → 不再上传
└─ 否 → 生成 clientUpdateId
         ↓
       WebSocket 发给 Java
         ↓
       等待 ACK
```

- 应用更新的时候会做这个检查
```typescript
// 如果更新来自服务器，则无需发送
if (origin === REMOTE_UPDATE_ORIGIN) return
```

## State Vector

- 来个宏观图
```txt
                    Yjs 同步层

Y.Doc
 │
 ├─ transaction
 │      ↓
 │   Update
 │
 ├─ encodeStateVector()     -- 一般情况不会很大，给的是进度条的大概数值
 │      ↓
 │   “我已经知道到哪里”
 │
 └─ encodeStateAsUpdate(doc, remoteSV)  -- 这个会很大，给的是能够恢复文档的完整 Update
        ↓
     “把对方缺的发给他”


                    CORE AGENT 层

nodeId
  ↓
定位对象

nodeHash / revision
  ↓
保证局部最新

operationId
  ↓
保证 Agent 操作不重复执行

Yjs Update
  ↓
Runtime / Provider 负责可靠传输与 CRDT 收敛
```

## RelativePosition & Awareness
- 相当于获取一个稳定的节点相对为位置
- 由于局限性，应该不好用于定位节点

- 更详细的模型
```txt
Awareness State
├─ user
│  ├─ userId
│  ├─ name
│  └─ color
│
├─ cursor
│  └─ relativePosition
│
├─ selection
│  ├─ fromRelativePosition
│  └─ toRelativePosition
│
└─ agent
   ├─ operationId
   ├─ status: reading / thinking / editing / idle
   └─ workingRange
```

## 节点内容
```txt
Node 本体
├─ nodeId           稳定身份
├─ type
├─ attrs
├─ content
├─ marks
└─ refId            resourceReference 节点专属（等价于 nodeId ）

并发保护
├─ nodeVersion
└─ nodeHash（可选）

位置体系
├─ ProseMirror pos       当前编辑器绝对位置
├─ Yjs logical index     当前共享类型中的位置
└─ RelativePosition      可随协同漂移的位置锚点

操作体系
├─ operationId
├─ Transaction + origin
└─ Yjs Update
```

## V1 版本留下的缺陷
- [ ] 多 Agent 之间的协同编辑能力并不完善（并非 Multi-Agent 设计）
- [ ] Agent 还不具备跨节点修改的能力
- [ ] 还不具备撤销 Agent 修改步骤的能力
- [ ] Agent 的操作步骤还未实现可追踪、可审计、可回顾（文档本身也暂时不支持）
