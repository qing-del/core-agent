# CORE AGENT：局部最新的协同编辑思想

CORE AGENT 是一个让真人与多个 Agent 共同编辑同一份文档的协同系统。

它不追求让所有参与者在任意时刻完全串行，也不以“整篇文档版本一致”作为修改前提；它的核心原则是：

> 文档可以持续变化，但一次修改必须基于其目标局部的最新状态安全完成。

## 核心概念

文档是实时协同的，真人和 Agent 都是协作者。

真人可以自由编辑；Agent 也可以阅读上下文、定位内容、提出或执行修改。不同之处在于，Agent 的每一次写入都必须经过明确的局部校验，避免因为阅读了旧上下文而覆盖真人刚完成的修改。

## 两种 Agent 编辑方式

### 乐观替换

适用于句子、段落、局部润色等小范围修改。

Agent 先定位目标内容，并记录其位置和预期内容。提交时，系统再次检查该局部是否仍然是 Agent 看到的版本：

- 若目标内容未变化，则完成替换；
- 若目标已被真人或其他 Agent 修改，则拒绝直接覆盖；
- Agent 重新读取该局部，再决定修改、提问或放弃。

这是一种面向局部内容的类 CAS 操作，而不是整篇文档的版本锁。

### 区域开辟

适用于生成大段内容、撰写方案、补充章节等场景。

当直接替换可能影响已有内容时，Agent 不抢占原区域，而是在附近创建一个新的协作区域，例如“Agent 草稿”“待确认方案”或“补充章节”。

这样可以让真人继续编辑原文，同时查看、修改、接受或删除 Agent 新生成的大段内容。

## 光标、选区与可见性

真人和 Agent 都应有可识别的协作身份：

- 不同颜色的光标；
- 当前选中内容的高亮；
- Agent 正在处理的区域标记；
- 清晰展示“谁正在编辑、谁正在思考、谁正在等待确认”。

这些状态用于协作感知，而不是直接决定写入权限。

## Agent "锁"的定位

Agent 选中的内容可以拥有短暂的“编辑租约”。

它的目的不是阻止真人编辑，而是告诉其他 Agent：该区域正在被处理，请避免重复工作或产生相互覆盖。

真人始终优先。如果真人修改了 Agent 正在处理的区域，Agent 应进入冲突状态，重新理解最新内容，而不是覆盖真人修改。

因此，锁本质上是协调机制，不是强制阻塞机制。

## 运行模式

### Ask 模式

Agent 生成修改提案，但不直接写入文档。

真人可以查看修改范围、修改内容和理由，再选择接受、拒绝或继续讨论。

适用于重要文档、多人协作和高风险改写。

### Auto 模式

Agent 在局部校验通过后自动执行修改。

如果目标区域已经变化、存在其他 Agent 租约，或修改范围风险过高，则自动降级为等待确认或重新规划。

适用于低风险润色、格式整理、补充草稿等任务。

## 冲突处理原则

冲突不是异常，而是协同编辑中的正常反馈。

当同一局部被多方修改时，系统不应简单采用“最后写入覆盖前文”，而应：

1. 保留真人已经完成的修改；
2. 阻止基于旧上下文的 Agent 覆盖；
3. 让 Agent 获取最新局部内容；
4. 重新生成合适的修改方案，或转为新区域草稿。

- Agent 局部乐观替换；
- Agent 大段内容区域开辟；
